# 同类项目调研与复用策略

日期：2026-09-11。范围：11 个 GitHub 项目和 Code Mode 架构参考。不是穷尽搜索。来源编号对应 [SOURCES.md](SOURCES.md)。

## 一、关键结论

“Agent OS”不是空白领域。电脑操作、批量动作、持久任务、权限与模型中间数据优化，都有现成路线。我们的机会仍是假设：把有限工作站任务的动作契约、产物依赖、失败恢复和证据整合成低维护成本的工具层。它必须胜过强基线，不能只胜过逐像素点击。

以下“复用/对照/暂缓”是本项目选型意见；能力栏是已读取的上游声明，未经实际执行验证。

## 二、项目矩阵

| 项目与来源 | 已有方向 | 与我们重叠 | 初步处置与边界 |
|---|---|---|---|
| [Microsoft UFO](https://github.com/microsoft/UFO) S01 | Windows 原生接口、GUI/API、批动作、跨设备 DAG | 直接覆盖桌面路由、批量与调度 | **首要对照**；先配置受控任务，不先复制整个编排系统 |
| [Cua](https://github.com/trycua/cua) S03 | 跨系统驱动、桌面环境、SDK、评测 | 设备接入、隔离与电脑资源 | **驱动/环境候选**；平台支持与背景输入需逐项确认 |
| [Rivet agentOS](https://github.com/rivet-dev/agentos) S04 | V8/WASM 虚拟 OS、进程/文件/权限、持久工作流 | 与原先“Agent OS 运行库”设想高度相似 | **运行库候选与直接竞品**；preview，不能当完整 Windows/Office 环境 |
| [AIOS](https://github.com/agiresearch/AIOS) S02 | Agent 内核、资源/上下文/存储/工具调度 | 名称和大部分抽象重叠 | **研究参考**；根 LICENSE 当前不足以确认授权，先澄清 |
| [OpenFang](https://github.com/RightNow-AI/openfang) S05 | 自主任务包、多渠道、状态、MCP、审计 | 广义 Agent 运行平台 | **系统结构参考**；不跟进全部渠道功能，不采信安全层数作证明 |
| [BrowserOS](https://github.com/browseros-ai/BrowserOS) S06 | 面向 Agent 的浏览器与 MCP | 浏览器工作空间、并行任务 | **独立软件候选**；不维护浏览器内核分支，许可与依赖单独评估 |
| [agent-browser](https://github.com/vercel-labs/agent-browser) S07 | CLI、语义定位、批命令 | 减模型往返、浏览器批处理 | **强基线与适配候选**；能批量本身不是我们的创新 |
| [Bytebot](https://github.com/bytebot-ai/bytebot) S08 | Linux 桌面容器、Agent 与观察界面 | 独立桌面/接管体验 | **历史参考**；页面已标示 2026-03-07 归档，不作默认维护底座 |
| [Agent S](https://github.com/simular-ai/Agent-S) S09 | GUI 操作研究框架 | 截图操作兼容层 | **后期基线候选**；模型/托管与 OSS 结果不能混算 |
| [Agno](https://github.com/agno-agi/agno) S10 | Agent 服务平台、审批、持久化与控制面 | 状态、治理、服务运行 | **上层框架参考**；不是 Windows 软件对象模型 |
| [LangGraph](https://github.com/langchain-ai/langgraph) S11 | 状态图、checkpointer、人工介入 | 持久化与长任务编排 | **复用候选**；图状态恢复不等于外部效果回滚 |

此外，[Cloudflare Code Mode](https://blog.cloudflare.com/code-mode/)（S12）解释了程序化组合工具与中间数据直传。我们提出的“少一次工具就少一次模型思考”并非新路线。

## 三、最值得深入的三个方向

### UFO：直接桌面基线

它已经靠 Windows 控件和原生接口减少纯截图路径，并用一次预测多步降低模型查询。上游所写“减少 51% 调用”是自己的实验/文档报告，不是我们可继承的结果。静态抽查确认存在动作与动作列表的结构；并未证明跨应用事务、全序列回滚或实际场景稳定性（S01a、S01b）。

选择动作：用同一批受控桌面任务评估它的配置成本、可观测性与失败模式。如果它已经满足需求，应优先集成，而不是为拥有自家 runtime 重写。

### Cua：电脑驱动与环境

设备驱动与沙盒生命周期不是我们的差异点。Cua 的平台边界需要仔细读，尤其背景输入、macOS 虚拟化条件及各系统权限。不能把“有 SDK”理解成所有能力在每个平台都一样（S03、S03a）。

选择动作：在独立测试环境中做一项最小驱动操作、一个拒绝用例和一次进程崩溃恢复；确认适配成本后再决定是否采用。

### Rivet agentOS：最接近“运行库形式的 OS”

该项目把虚拟文件、进程、网络能力及受控外部绑定放进嵌入式运行库；同时已有持久工作流。它的存在直接削弱了“我们来发明 Agent OS 基本抽象”这一定位（S04）。

选择动作：把任务/产物 API 设计为后端可替换。验证其与本地原生应用桥接是否简单；preview API 的变动成本需要记录。不因为其冷启动数据好看就推断我们的长任务更快。

## 四、复用决策

| 层 | 当前默认 | 改选条件 |
|---|---|---|
| 浏览器 | Playwright 与 agent-browser 做同任务对照后选一个 | 更低维护成本、结果更可检查者优先，不同时写两套产品适配 |
| 桌面驱动 | 暂无强制依赖，后期评估 Cua/UFO | 首版效果得到证明且实际电脑环境确认 |
| 任务思考与重规划 | 由现有 Agent 承担 | 确需动态工作流时再选 LangGraph 等，不自研通用 Agent 框架 |
| 确定动作执行 | 有限 DAG、动作日志与产物 API | Rivet/其他库满足边界并降低成本时用后端实现替换 |
| 隔离环境 | 首版仅合成输入+受信适配器；不宣称安全沙盒 | 执行不受信代码前，必须采用并验证 OS/VM 级边界 |
| 数据状态 | 单机 SQLite 与本地产物库 | 单机成为真实瓶颈时再考虑外部服务，不预建分布式架构 |

## 五、维护与许可风险

本表仅是技术选型核验事项，不作法律意见。正式引入仍需读具体版本、子目录和传递依赖许可。

- UFO 的本次动作源码头为 MIT；Cua 根许可为 MIT，但可选组件另有许可，不能一律视为 MIT（S01b、S03）。
- Rivet agentOS、agent-browser、Bytebot、Agent S、Agno 的页面标注 Apache-2.0；采用时仍需保存相应 NOTICE/版权信息（S04、S07—S10）。
- BrowserOS 的根 AGPL-3.0 与其浏览器依赖需要另做分发方式评估，不直接复制到我们的 MIT 代码库（S06）。
- AIOS 的根 LICENSE 本轮读取只有一个换行字符；需联系维护者或核实明确授权后再引入代码（S02a）。
- Bytebot 归档与 Rivet preview 是维护信号，不是“不可用”的绝对判断（S04、S08）。
- 本轮没有对 OpenFang 的全部依赖与各子目录做许可核对；不把 README 的许可简写当成传递依赖结论（S05）。

## 七、对项目定位的最终影响

先做可测量的“执行层实验”，不是宣布新操作系统。保留公开负面结论：若上游的批处理已经解决主要问题，本项目可收敛为适配器、测试与安全约束示例；无需扩成平台。
