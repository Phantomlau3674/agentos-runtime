# 风险登记与应对

| 风险 | 优先级 | 预警信号 | 处理方式 |
|---|---|---|---|
| 现成工具已覆盖价值 | 高 | B 的人工介入与恢复已满足需求 | 收敛为集成/适配器，停止通用层开发 |
| 收益只来自弱基线 | 高 | 只有截图点击对照显著，B→C 无增益 | 强制 B 基线与消融实验 |
| 结果好看但不正确 | 高 | 只有状态成功，没有数值/对象证据 | 独立 oracle 和目标级验收 |
| 外部效果未知时重试 | 高 | 写后丢响应触发自动重复写 | unknown_effect、幂等查询、人工判断 |
| 宿主权限被误认为已隔离 | 高 | Agent 另有 Shell/插件却宣传整机安全 | 公开信任假设；必要时隔离运行后端 |
| 路径/网络逃逸 | 高 | 子资源/链接未覆盖策略 | 句柄级处理、快照、网络环境限制、负例 |
| 批次失效与并发冲突 | 高 | 手动修改后仍用旧计划、同资源多写 | 版本复核、资源键、失效子图与停止 |
| 用户无法自行排错 | 高 | 失败需要改源码或读长堆栈 | 可读错误、诊断包、保留产物与单步恢复 |
| 上游 API/平台变化 | 中 | preview 版本升级频繁破坏集成 | 固定版本、隔离适配边界、留替代方案 |
| 许可不清或组合复杂 | 高 | 缺 LICENSE、混用可选依赖许可 | 核对具体版本，未澄清不复制代码 |
| 范围扩张 | 高 | 首个任务未过就同时做 UI/3D/Office/多机 | M5 单独 gate，不抢占 M1—M4 |
| 维护成本吞掉收益 | 高 | 每次应用升级都需大量修复 | 统计维护人时，只保留高价值接口 |
| 测量不可信 | 高 | 忽略失败、Token 缺失填 0、只报最优样本 | 全量记录与预设统计计划 |
| X 证据缺失被误读 | 中 | 把空结果写成无竞争 | 保留检索失败，不补造帖子 |
| 公共仓库意外泄密 | 高 | 导入聊天记录、个人配置或运行数据 | 合成 fixtures、禁止文件模式、人工预览与扫描 |
| 环境与授权不确定 | 高 | 假定已能操控所有原生软件 | 先验证实际 OS/应用/权限，未测写明 |

## Stop-ship 事件

原始数据被修改、越界写、秘密泄露、Agent 自我批准、未知效果被盲重试、测试结果伪造，任一发生就停止预览发布并修复。仅仅提高某个性能指标不能抵消这些问题。

## 决策日志

每个阶段记录继续、调整或停止，附证据和未决问题。保留负面结果；不得在复盘时把原始目标改成“只要能演示就成功”。
