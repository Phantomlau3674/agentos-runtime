# ADR 0013：输入一致性合同——快照语义

状态：已实施（REV-008；语义早已隐含，本 ADR 将其显式化并补充已定义行为测试）。

## 决定：snapshot（快照语义），不是 follow-latest、不是仅发布前校验

- `inputs.snapshot` 节点一次性有界枚举并读取输入，字节同时用于聚合与 `snapshots/` 只读副本；后续节点处理的是快照字节，源目录之后的漂移不改变本次计算。
- 终态复核（`verify` 的 `source_unchanged`）在发布前重读输入哈希：快照后源目录被修改则核验失败——宁可交付失败也不交付基于旧输入的结果。
- `resume` 要求输入哈希与快照回执一致（`INPUT_CHANGED`），不允许在新输入版本上沿用旧回执。
- 漂移对调用方显式可见：`task_inspect` 的 `observation.stale`（REV-010）。
- `snapshots/` 副本独立成立：源目录被删除/替换后快照字节不受影响，可作为恢复核对的依据。

已定义行为（有测试）：快照后修改 → 运行失败 `INPUT_CHANGED`、不交付；快照后删除/新增/内容变化 → 恢复时 `INPUT_CHANGED`；同路径被目录替换 → `UNSUPPORTED_FILE`（只接受普通文件）；源缺失时 `stale='unknown'`。

## 被拒绝的备选

- follow-latest：恢复与核验面向移动目标，无法绑定结果到确定输入版本。
- 仅发布前校验：聚合基于未固定的输入流，崩溃窗口语义不清。

## 边界

快照语义绑定的是"本次运行的输入版本"，不是承诺源目录永不变；那由 stale 标记与恢复门禁承担。多版本并发读取、跨任务输入缓存属于 REV-014 范围。
