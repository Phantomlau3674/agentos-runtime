# ADR 0005：先交付离线合成任务技术验证，不冒充完整运行时

日期：2026-09-11。状态：技术验证采用；平台 go/no-go 仍未决。

## 原因

需要从策划进入可测试代码，又没有已授权的本地电脑、真实模型预算和完整 A/B 基线。本轮只实现有界工程验证，不能据此放行完整平台建设。

## 决定

1. 新接口名为 `aor.fixture-plan.v0.1`。完整 `aor.task.v0` 文档仍为设计稿。不能以这个四阶段顺序链声称实现通用 DAG、opaque artifact API 或全部计划权限。
2. 输入路径、workspace、oracle 和 Policy 由本地测试所有者提供，不接受模型计划自行设置权限或主机路径。只接受生成器产生的合成 fixture。
3. 金额限定两位小数、数量为正整数、四种明确币种；重复 ID 的第一条合法 ID 出现保留 ID，即使其余字段无效。规则有测试，不默默取整或跨币种相加。
4. 聚合用 Decimal；fixture 标准答案在生成时用整数分计算，核验持久化产物，不调用聚合函数重算同一路径。
5. 运行事件持久化到 SQLite，文件先写 staging。成功核验后移动为 outputs。现阶段没有跨 SQLite/文件系统事务或目录 fsync 的断电一致性承诺。
6. 输入目录被读取、快照、重新核对哈希；源文件不由本项目修改。目录不是操作系统级只读挂载，快照也不是防同用户恶意程序的强隔离。
7. 超时在动作边界与读取循环检查，是协作式预算，不是抢占式沙箱限制。没有任意脚本执行或外部网络操作。
8. 进程崩溃后保留事件/产物，不自动恢复，拒绝复用已存在 workspace。记录为 RUNNING 且进程不存在的情形需后续对账，并不是仍有后台任务运行。
9. 干净安装、Windows 原生测试、Agent 集成和完整强基线未完成。不得标对应大任务已结束。

## 后续

先补安装与平台验证、文件 staging 中断对账，再按原依赖接 MCP。只有真实基线支持继续时，才扩展通用任务契约、浏览器与模型循环。
