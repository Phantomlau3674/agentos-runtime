# 路线与阶段验收

日期不作为未经验证的工期承诺。当前计划只定义依赖和退出门槛；正式估工在 M0 基线和环境实验之后更新。

| 阶段 | 核心工作 | 阶段演示 | 禁止跨越的门槛 |
|---|---|---|---|
| M0 | 合成输入、oracle、A/B 基线、上游选型 | 同一批任务的现有方式与批处理差异 | 未发现强基线缺口就不扩大平台 |
| M1 | 类型契约、策略、状态、产物、串行批次、验收 | 一次提交得到可核验输出，源文件不变 | 只生成文件不等于正确交付 |
| M2 | 崩溃恢复、局部失效、有限并行、取消、审批 | 杀进程后恢复已验证成果，未知效果停止 | 无法对账的效果不得盲重试 |
| M3 | Browser/mock 草稿、MCP、第二任务族 | 现有 Agent 调用一个 Runtime 完成两类任务 | 没有复用就不是通用层价值 |
| M4 | A/B/C 试验、安全回归、诊断、安装与预览 | 全新环境独立复现，公开成功与失败 | 无证据不宣传性能或安全性 |
| M5 | 原生桌面/创作/文档/隔离后端等条件项 | 每项只试一个有价值场景 | 每项单独计算收益与维护成本 |

## 关键依赖

基线与范围决定 → 契约/策略 → 状态与输入快照 → 适配器/串行执行 → 结果验证 → 恢复与有限并发 → Agent 接入与第二任务 → 证据与预览。

公开仓库创建不阻挡本地合成测试设计，但会阻挡远端提交与 Issue 发布。X 复核不是运行时开工的技术依赖；不得因为无法读 X 正文便编造结论。

## 估工方法

将任务按可交付切片细化，估计实现、联调、安全/故障测试和文档交接四部分；不要把生成代码耗时当总工期。记录每个适配器的未来维护责任。只有人员投入、目标机器和上游复用实验明确后再给日历计划。

当前清单有核心任务、条件任务和待补研究三类，不能把全部数量直接乘以固定人日。M5 不是首版的隐含交付承诺。

## 不继续的结果也可发布

若 B 已解决需求，保留测试集与基线配置；若差异只来自适配器，发布适配器；若 Runtime 确有增量，再推进原生软件扩展。项目不会为了保持“OS”命名而持续扩大范围。
