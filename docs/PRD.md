# 产品需求 PRD

状态：设计稿，未实现。验收与任务追踪分别见 [BENCHMARKS](BENCHMARKS.md) 和 [BACKLOG](../planning/BACKLOG.md)。

## 用户问题与成功定义

用户希望同一模型完成电脑任务时，减少等待、逐步指挥和失败重做。任务最终质量、原始资料完整性与可撤回授权是硬约束。不是追求更长的自主运行时长，更不是增加工具数量。

北极星指标是“每个合格交付占用的人类时间”。同时报告端到端时间、失败、模型调用和总成本，避免把人工时间转嫁成不可接受的机器等待。

## 功能需求

| 编号 | 需求 | 通过条件 |
|---|---|---|
| FR-01 | 任务带输入、目标、限制与验收器 | 缺失任何必要字段时不执行 |
| FR-02 | 有界批量执行 | 一次提交允许多个注册动作，但每个动作都有独立状态、授权检查和结果 |
| FR-03 | 中间数据只用引用传递 | 大产物不默认回传模型；可按权限读取有限摘要 |
| FR-04 | 结果可验证 | 成功状态必须对应独立验收结果与产物哈希 |
| FR-05 | 重启后恢复 | 已核验节点复用；未知副作用不盲目重试 |
| FR-06 | 输入变化可发现 | 输入/对象版本变化导致相关节点失效，不悄悄复用旧结果 |
| FR-07 | 权限与预算 | 越界目录、未授权域名、禁止效果和超额计划被拒绝 |
| FR-08 | 人工暂停/取消 | 取消后不再派发新动作，说明已产生的产物/未知效果 |
| FR-09 | 现有 Agent 接入 | MCP/CLI 共用同一执行逻辑与策略，不有一条较宽松后门 |
| FR-10 | 观察与解释 | 用户看得到在做什么、完成什么、剩余什么以及失败影响 |
| FR-11 | 本地优先 | 默认没有遥测；日志与合成产物本地保存，导出前脱敏 |
| FR-12 | 支持清单 | 每个适配器声明版本范围、平台、效果类型、恢复规则和未支持场景 |

## 首版任务族

T1：合成目录数据汇总与校验，重点批处理和数据直传。T2：受控本地网页草稿与核验，重点状态、等待、草稿重复提交与局部恢复。T3：可选合成文件整理与清单生成，重点分支并行和哈希依赖。

T1 与 T2 都通过，才能说运行时有跨场景复用；它们仍不足以支持“所有桌面软件”的结论。Blender/Office 留待 EXP 系列任务。

## 输入与交互

任务发起人选择项目目录和输出副本位置，明确预期产物。默认不获取整个硬盘权限。模型计划在执行前生成可读说明：读什么、写什么、是否涉及外部效果、估计资源上限与哪些点需人确认。

用户看到的状态语言：准备检查、正在处理、等待确认、需要判断、完成并通过检查、失败但已保留成果、已取消。每条状态都能对应程序状态；不能靠模型一句“做好了”结束。

## 非功能需求

数据正确性使用确定验收器；初始金额规则使用 Decimal 或整数最小单位。源文件只读、输出新版本。任务状态与产物索引持久化；SQLite 单写者，适配器返回统一错误结构。运行额度和输出大小都必须有上限。

v0 仅接受受信适配器，不承诺抵御同一宿主账户的恶意进程。没有真实环境测试就不标为支持；CPU/GPU 不足时排队，不宣传无限并发。

## 发布界限

首版叫本地实验预览，不叫生产级 OS。只有合成任务与指定软件组合是支持范围。预览发布说明必须列出未通过测试、已知限制、是否会调用模型及费用控制办法。
