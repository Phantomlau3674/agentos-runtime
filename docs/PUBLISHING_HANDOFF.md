# 远端发布接续说明

当前状态：本地策划文件已生成；GitHub 远端仓库、提交、Issues 和 Milestones 尚未创建。

## 当前限制

当前连接能读取账户与仓库，并能在已有仓库创建文件、分支、提交和 Issue；没有创建新仓库的接口。不能把 create_file 用在不存在仓库上假装会自动创建，也不能改动其他仓库来绕过限制。

## 所有者的最小动作

到 GitHub 的新建仓库页面创建 `agentos-runtime`，设为 Public，并初始化 README。不要向聊天提供任何访问令牌、密码或 Cookie。提供实际仓库链接即可。

## 后续工具执行顺序

1. 读取给定仓库元数据、默认分支和 README，确认正确所有者、公开属性与当前写权限。
2. 读取现有文件/版本；若已有内容，不强行覆盖。新建计划分支并上传本包中需要的文件。
3. 用所提供的文件 API 或 Git tree/commit API 提交，保留当前 base SHA；不要 force 更新。
4. 创建文档 PR 或在明确授权下合并；写入真实提交 SHA 和链接到 STATUS。
5. 按 planning/backlog.json 创建需要的 Issues，记录真实 issue_number。没有调用 create_issue 就不标已创建。
6. 当前没有 Milestone/Label 创建接口时，继续在正文中使用 M0/P0 等计划元数据，不虚构 GitHub 原生对象。
7. 上传完成后读取 README、STATUS 和任务索引核验，再报告实际完成内容。

任何权限失败都应停止相关写操作，不能请求用户粘贴秘密或修改无关仓库。公开文件只包含此项目策划与合成示例规范，不上传私人聊天记录。
