# 架构设计

状态：设计决定，不是已实现系统。ADR 记录见 [DECISIONS](DECISIONS.md)。

## 1. 边界

现有 Agent 负责自然语言理解和有必要的重新规划；Runtime 负责校验并执行注册动作。上层是否使用某一模型或框架，不改变底层执行权限。绝不将工具列表中所有可用工具自动授予每个任务。

第一版为单机模块化进程结构，而非微服务：一名状态写入者、受控 worker、SQLite、产物目录、CLI/MCP 入口。仅在原生应用需要时另启应用会话内 worker。复杂度必须对应已有需求。

## 2. 组件与职责

| 组件 | 接收/输出 | 不承担的职责 |
|---|---|---|
| Protocol facade | MCP/CLI → TaskSpec、状态、摘要 | 不直接执行应用动作 |
| Plan validator | 校验 schema、版本、依赖、预算、注册能力 | 不把自然语言编译成任意主机代码 |
| Policy broker | 已解析参数与目标 → allow/deny/approval_required | 不信任模型自报的 read_only 标签 |
| Executor | 已批准节点 → 调用/超时/取消/状态事件 | 不自带通用 LLM 规划器 |
| Resource manager | 资源声明 → 有界并发与租约 | 不调度本地大模型 GPU 推理 |
| Artifact store | 内容、哈希、权限 → 不透明句柄 | 不把句柄当文件系统任意路径 |
| Journal | 原子状态变化与操作意图 → 重启恢复依据 | 不伪装为所有应用的 ACID 事务 |
| Adapter registry | 能力名/版本 → 受信实现与效果声明 | 不自动安装社区插件 |
| Verifier | 产物/原始输入 → 结构化通过/失败证据 | 不只询问同一个模型“是否做好” |
| Human control | 查看、批准、拒绝、取消 | 不把审批凭据交给 Agent |

## 3. 计划进入系统后的路径

接收 TaskSpec → 结构与大小校验 → 锁定不可变 plan_hash → 导入输入清单/版本 → 对能力和静态效果做预检查 → 写入任务与节点 → 按依赖调度。

每一步在派发前解析引用，重新检查解析后的实际资源和效果、最新策略、输入版本、额度和审批有效性。合法才写 operation intent，再调用适配器。执行后记录结果、核验产物和后置条件，最后将节点置为 verified。只有所有目标验收均通过任务才成功。

动态观测不符合预期时，停止当前批次并返回差异；上层提交新计划版本。v0 不允许正在执行的 DAG 被原地改写。

## 4. 数据设计

SQLite 表建议：tasks、task_nodes、operations、events、artifacts、artifact_links、approvals、resource_leases、schema_migrations。所有可见 ID 采用随机标识；跨任务访问需要显式权限，不从 ID 猜目录。

事件用于审计与恢复诊断，关系表是可查询状态。使用数据库事务保持一次状态转换与相关事件一致；不是宣称已构建无限 event sourcing 平台。SQLite 文件与本地 blob 内容不能组成跨存储事务，要用 staging、原子 rename 和重启对账处理孤立文件。

外部引用只暴露 task_id、artifact_id、schema/type、digest 与允许的摘要。原始输入内容保存在产物库或者授权源中，不进入所有 LLM 请求。摘要不是可靠事实来源，核验始终回到实际内容。

## 5. 执行计划表达

使用有版本的 JSON Action DAG。节点调用预注册动作，参数只能是字面量或显式产物/前序结果引用。v0 不支持 eval、任意条件表达式、未声明副作用或无界循环。批处理在受信动作内部用确定程序处理集合，逐项报告失败。

一个文件处理节点可以处理整个授权清单，不强制 100 个文件变成 100 次模型调用。底层逐文件检查和权限校验仍发生，只是不需要 LLM 逐项参与。

## 6. 技术选型草案

Python 便于首期文件/数据和浏览器集成；Pydantic 验证模型与导出 JSON Schema；SQLite 支持单机持久状态；pytest 等用于测试。具体兼容版本与锁文件归 GOV-003，策划包没有伪造已锁定依赖。

浏览器二选一：Playwright 库适配，或 agent-browser 常驻会话 CLI 适配。先评估运行复杂度、数据回传量和故障行为再固定，不同时维护两个产品实现。[来源 S07、S13](research/SOURCES.md)

LangGraph 只作为上层动态编排候选，避免双重调度；Rivet 可替代执行/隔离后端，但需先验证本地应用桥接和生命周期。数据契约保持不依赖某框架私有对象。[来源 S04、S11](research/SOURCES.md)

## 7. 并发与资源

初始串行。加入并发后按文件写入范围、browser profile、原生 app instance 和任务工作目录加资源键。只读不可变输入可以共享，写操作需要独占或适配器可验证的版本控制。资源锁不把未受本系统控制的外部程序锁住，执行前仍需要复核版本。

进程执行必须有总数、时限与输出大小限制。一个已饱和 GPU 的两个任务不能靠逻辑并行获得额外算力；渲染、应用实例等重资源能力默认排队。

## 8. 安全边界与未来演进

v0 是 trusted-local 运行模式：可信实现处理不可信结构化数据，不执行任意来自模型的代码。浏览器页面本身是敌对输入，需阻断网络越界并隔离会话；浏览器 context 不是对宿主恶意代码的沙盒。

后续引入模型生成代码前，优先选现成隔离运行库/虚拟机，而不是加一层 Python subprocess 就叫隔离。完整控制面的能力安全依赖所有外部通道都被约束；不在本 Runtime 内的 Shell/插件不会被神奇接管。
