# Agent 集成与能力保留

日期：2026-09-11。状态：能力保留要求仍待真实客户端验收；v0.0.2 已实现传输无关网关与 CLI 协议测试，详见 TOOL_GATEWAY.md。没有 MCP 或真实模型联调结果。

## 接入原则

首版作为现成 Agent 的工具，不取代模型、会话或工具循环。

```
用户 → 现成 Agent（模型/会话/Skills/上下文/观察/重规划）
                       ↓ MCP 或 CLI
           Runtime（计划校验/策略/执行/产物/证据）
                       ↓
                   受信适配器
```

模型分阶段规划而非一次性预测到底。确定执行连续运行，新的信息或异常影响计划时返回 Agent。外部内容是数据，不赋予权限。人类批准不提供 Agent 自我审批接口。

## 必须保留的能力

| 能力 | 验收要求 |
|---|---|
| 模型工具循环 | 工具结果能回到原会话继续判断，不另造失联会话 |
| 动态重规划 | 新信息能使未执行旧计划失效 |
| 会话与上下文 | 客户端原生记录和通用任务记录分开保存 |
| Skills/项目规则 | 文件发现、按需加载、脚本资源与工具映射经过测试 |
| 项目记忆 | 偏好/决策与实际执行事实分离，不能用模型说完成代替核验 |
| 原文和多模态证据 | 摘要不阻止有权限的进一步观察；截图/图片不盲转文本 |
| 编码和探索 | 增强模式保留原客户端工具；受管代码需独立沙箱，不冒称全机受控 |
| 子 Agent | 单任务只保留一个决策主控，委派范围明确，不共享无限权限 |
| 人工打断 | 取消和新约束在动作边界生效，已发生效果需解释 |
| 异步完成 | 程序接收任务事件并唤醒正确会话，不用大模型忙轮询 |
| 原生会话状态 | 保留供应商规定的调用关联/状态项，不承诺跨供应商原样移植 |
| 预算和诊断 | 模型与动作分别计量，统一关联任务，不伪造缺失指标 |

## 两个边界

增强模式只能约束经过 Runtime 的动作。原 Agent 的无限 Shell 等工具仍在边界外。

受管模式需要所有资源访问经过权限代理和环境隔离；不能靠 MCP 或提示词达成。它不是当前离线技术验证已实现的功能。

## 测试门槛

以接入前的客户端为基线，覆盖已有项目/Skills、计划改变、跨会话继续、人类修改、未知效果、成本和质量回归。接入一个工具成功不代表上述能力全部保留。
