## 1. frozen 并非深层不可变

在 default_plan() 上执行 `plan.nodes[1].depends_on.append("not_a_node")` 成功，plan_hash 随之变化。再次用 PlanSpec.model_validate_json 校验时拒绝了该计划。当前 _preflight 会重新校验并创建副本，因此这个实验不是越权利用证明。

建议：外部 wire model 与内部不可变 CompiledPlan 分离。内部仅持有 tuple/frozenset/不可变节点和 bytes 等递归不可变数据，受信编译入口生成规范化字节和哈希。不在完成该改造前贸然缓存可变对象的哈希，不删除外部边界验证和动态权限检查。

## 2. 分页读取的隐藏工作量

合成任务：100 份 CSV、每份10行。请求 errors.json 的连续三个分页，每页一个 Unicode 字符。
每次先校验所有四份产物，再完整读取目标 errors.json：总计5次逻辑产物读取，84,554字节。目标文件本身41,003字节。
这是逻辑读取计数，不是物理磁盘 I/O 或耗时测试。

建议：状态元数据和当前完整性验证分开表达；用绑定内容摘要的读取会话、经过验证的不可变字节快照或可校验的分块存储实现真正分页。必须说明读取的是快照还是当前磁盘版本，不能用mtime代替完整性保证。UTF-8字符偏移不能直接作为字节seek偏移。

## 3. 汇总内核候选优化

现有 setdefault 的默认分组字典及 Decimal(0) 每个有效行都会构造；localcontext 在每个有效行进入。候选A仅在分组不存在时创建默认值；候选B在A基础上按当前“非负、最多两位小数单价、整数数量”的契约使用整数分。

62组独立合成输入逐字段对照原始Decimal实现，全部一致。包含无效字段、跨文件重复ID、前导零，以及3000行极大值累加超过int64的情况。这不是穷尽证明或完整项目回归。

20文件、共20,000有效行、7轮随机顺序的同进程计算内核实验：

| 实现 | 中位耗时 | 相对原版耗时下降 |
|---|---:|---:|
| 原版 | 59.89 ms | — |
| 延迟创建分组 | 55.61 ms | 7.1% |
| 整数分＋延迟创建分组 | 39.22 ms | 34.5% |

此实验不包含模型、网络、磁盘和运行时；不推算端到端提效。小样本、无系统CPU隔离、无置信区间。只可作为选择下一项工程优化的证据。

金额契约若扩展到汇率、任意精度、利息或其他舍入规则，不能直接复用整数分内核。当前允许范围内整组累计可超过64位整数；原生实现须做范围证明、checked arithmetic或使用更宽整数。

## 4. 当前 MCP 接口的静态风险

固定提交的 mcp_server.py 已用官方 SDK，将所有工具经同一 anyio.to_thread.run_sync 路径执行，设置 abandon_on_cancel=True。取消请求的等待不等于取消底层工作；未在本轮运行该模块。

建议：区分短控制请求与长执行请求，保留独立调度额度和有界队列。用持久取消状态及安全点处理业务取消，不声称杀进程能撤销外部副作用。

## 5. 任务编译器建议（尚未实现）

Wire request -> type/schema validation -> immutable logical IR -> effects/alias/dependency analysis -> guarded optimizer passes -> physical plan -> execution/verification.

优先考虑常量绑定、共同纯计算复用、受条件约束的批处理、内存生命周期分析。不得消除验收/权限/审计语义，不越过外部副作用和持久化边界。异常、终止性、取消、预算也属于适用条件。

先用受限Python执行器运行IR；保留参考解释执行路径，逐项做优化前后结果、错误和外部效果的差异测试。所有原生编译器/编译标志、编译缓存与图优化均是建议，没有在本轮实现或测量。
