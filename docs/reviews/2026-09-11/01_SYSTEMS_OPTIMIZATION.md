# 系统层：从执行器到有语义的任务运行时

状态：提案。历史代码观察见 [证据说明](05_EVIDENCE_AND_REPRODUCTION.md)；本文件不是性能实测报告。

## 1. 先建立性能模型

按任务关联模型推理、网络等待、序列化、数据读取、计算、资源排队、验收、恢复和人工介入。并行任务看关键依赖路径，不能把所有节点的耗时相加后当作墙钟时间。

Amdahl 定律的设计启示：优化占比很小的本地代码，无法解决主要由模型等待造成的延迟。假设模型等待占90%、本地执行占10%，把本地执行加速100倍，整体加速也只有 `1/(0.9+0.1/100)≈1.11`。这是算例，不是项目数据。

建议采用 trace/span 关联计量。分别记录模型调用次数、输入输出 token、工具执行、锁等待、序列化字节、逻辑读取字节、恢复重做、人类主动操作时间。端到端指标是满足目标合同的交付时间与总成本，不是工具调用数最少。

## 2. 受信动作契约

当前固定四阶段只是验证切片。扩大到通用任务前，让受信适配器声明：输入输出类型、读取集、写入集、资源作用域、外部效果、前置条件、验收条件、重试与恢复策略、超时及资源需求。模型可选择动作和参数，不能自行声明动作是纯函数或自行扩大权限。

有了这些属性，编译器才可以判断同一输入能否复用、动作能否合并、资源是否冲突。静态依赖分析不取代执行前的版本和授权校验。不能把动作函数名相同当成语义相同。

## 3. 分离决策与数据传输

模型传规则、输入引用、产物引用、约束和需要调查的问题；受控执行程序直接读取、过滤、传递和写入数据。结果返回摘要、异常类别、证据引用，允许按权限展开原文。

先减少数据经过模型读一遍再生成一遍，不立即建设共享内存或零拷贝系统。测出本地序列化和复制是瓶颈后，才选批量缓冲区、分块或其他通道。

MCP 是连接协议；API、CLI、GUI 是具体执行路径，不是同一层的互斥选项。先确认语义和权限等价，再按成本选择路径。API 不完整时不能为了少点鼠标而丢掉验收要求。

## 4. 明确输入一致性，才能减少重复扫描

历史审阅记录在100文件任务中看到原始输入完整读取7次，属于逻辑读取而非物理磁盘测量。不能直接删除检查；先选择输入语义：

| 模式 | 承诺 | 实现方向 |
|---|---|---|
| 固定快照 | 本任务以明示版本计算 | 获取并验证一次快照，内部使用版本化引用 |
| 交付前仍有效 | 基于快照计算，提交前确认来源仍满足约定 | 发布前检查源版本或执行条件 |
| 跟随最新输入 | 输入变化使受影响产物失效 | 事件检测、依赖失效与局部重算 |

只读副本不等于外部源被冻结；两次哈希相同不证明期间没有变化。多文件读取还需要说明是否为同一逻辑版本；没有快照事务、锁或源版本机制时，不承诺原子多文件视图。

## 5. 增量计算与恢复不同

恢复复用同一次任务中已核验的阶段；增量计算复用不同修订之间仍成立的结果。缓存键至少覆盖输入内容及影响含义的元数据、动作实现、参数、配置与相关环境。

时间、随机种子、网页状态、字体、文件名排序和软件版本可能是隐藏依赖。无法枚举依赖的外部状态不应默认缓存。当前 engine_fingerprint 是保守绑定；未来可固定历史执行器并做按动作版本迁移，不直接取消指纹检查。

跨文件重复 ID 是重要反例：整体处理得到10元和一个重复异常，分文件汇总再相加得到30元且漏掉异常。可以独立解析并缓存文件，但按既定文件名/行顺序统一裁决 ID，再汇总。未经语义分析不能套 Map/Reduce。

## 6. 按事件返回模型

模型规划当前一段；程序执行明确步骤，持续检查可程序化条件。只有新歧义、条件失效、无法解释的错误或新的授权需求，才返回 Agent 或人类控制面。

探索与批量执行采用不同节奏。不能为了减少模型次数而删掉观察、权限和验收，也不能用模型自报置信度直接决定是否跳过保护。先用规则和证据定义返回条件，再考虑基于历史数据校准。

长任务等待由宿主程序处理，完成事件关联任务与会话；不要每隔几秒调用模型问是否完成。事件重放、重复通知和宿主重启必须不会重复触发副作用。

## 7. 依赖与资源共同调度

区分逻辑数据依赖和资源冲突。独立文件可能并行；同一文档、浏览器会话或已满载 GPU 可能需要串行或限额。采用有界队列、资源键、短锁和独立控制通道，不以多开 Agent 代替调度。

单机阶段保留 SQLite，按测量处理写争用。不要在数据库事务里等待模型、渲染或网络。WAL 的部署限制和单写入者约束需要核对；不要把它放进跨机器共享文件系统以冒充分布式数据库。

## 8. 恢复按效果分类

纯计算可重算或缓存；受控文件创建先核对产物；支持幂等的外部写入复用原执行标识并查询结果；结果未知且不支持幂等的动作进入 unknown_effect，先对账。任务恢复不等于外部行为回滚。

分别保留请求编号、动作执行编号和内容哈希。相同参数可能表示两次不同意图，不能一律按参数去重。Agent、运行时、适配器共享总截止时间与重试预算，防止分层重试相乘。

## 9. 缩小可信核心

受控动作走权限代理；执行器只获取所需资源能力。外部 Shell 仍不受本系统保护时，明确标记增强模式而非整机受管模式。

审批绑定主体、动作、解析后的目标、输入/产物版本、计划及有效期，变化就失效。WASI 等隔离方式只是候选后端；文件路径检查不是完整沙箱，不声明对恶意同用户进程安全。

## 10. 优化必须可被否定

保留 A/B/C：逐步 Agent、同权限的成熟批处理基线、加运行时。B→C 才反映运行时增量。另做每个优化的消融、冷/热缓存、故障/无故障、一次性/重复任务和未见输入测试。

既报告合格率、假成功、拒绝和人工成本，也报告中位与尾部耗时、维护成本。已存在的强基线足够时，允许停止扩大平台。不得通过去掉安全检查或只测成功任务制造收益。
