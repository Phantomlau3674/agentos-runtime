# REV-019：原生实现实验——不引入（否定决策）

日期：2026-09-11。分支 `rev-001-002-measurements`。

## 实测

本机（Windows，Python 3.12.14），200 文件 / 20,000 行合成 fixture：

| 指标 | 值 |
|---|---|
| 端到端 `Runtime().run` | 6.833 s |
| `tabular.aggregate` 内核（整数分） | 0.0355 s |
| 内核占端到端比例 | **0.52%** |

## 结论

**不引入 mypyc/Cython/Rust 候选。**即使原生实现把内核降到零，端到端也只能省约 0.5%——净收益严重不足，不满足"净收益不足则不引入"的门槛。端到端时间花在快照拷贝、核验重读与磁盘写入，不在聚合内核。

PGO/LTO 评估的前置条件（先证明热点）未成立，不再展开。

## 若未来重新评估的触发条件

- 单任务输入规模提升一个数量级以上，且基准显示内核占比显著上升；
- 或新增计算密集动作类型。

届时再按原流程做候选选型、批次接口、构建/调用成本与冷/热/端到端全套测量。
